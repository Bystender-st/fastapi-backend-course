1) При хранении задач и всей сопутствующей информации в оперативной памяти главный минус будет в постоянном сбросе(потере) всей добавленной информации за сеанс при каждом перезапуске сервера.

2) После замены оперативной памяти на файл .json данные хранятся в постоянной памяти и доступны даже при перезапусках сервера проекта. 
Но от хранения состояния не избавились, так как все равно нужно хранит данные между сенансами, только теперь в постоянной памяти.
Возможные альтернативы:
 - Встроенная база данных (SQLite) 
Плюсы: Поддерживает SQL — можно делать выборки, сортировки, фильтры. Более надежно по сравнению с хранением в файле. Удобно - встроено в Python.
Минусы: Если несколько пользователей начнут работать одновременно — могут быть ошибки. При этом использовать их сложнее чем json файлы. Не умеет работать с несколькими процессами. Огранеичение производительности для больших файлов. 
 - Серверные базы данных.
Плюсы: Можно использовать многими пользователями одновременно. Поддерживает сложные запросы — удобно делать выборки, сортировки, связи между таблицами. Ещё более надёжно, чем встроенная база данных. Высокая масштабируемость - может работать с огромными объемами данных.
Минусы: Более сложная настройка и использование. Более высокие системные требования. Избыточна для небольших проектов.
 - NoSQL — документная база.
Плюсы: Можно хранить вложенные списки, словари и JSON-подобные объекты. Гибкая структура и масштабируемость.
Минусы: Менее надёжно чем серверные базы. Структура данных не контролируется. Сложно проверять ошибки. Нет мощных SQL запросов.
 - Облачные базы данных.
 Плюсы: Не нужно устанавливать и настраивать базу данных. Провайдеры сами делают бэкапы и обновления. Масштабируемость.
 Минусы: Прямая зависимость от провайдера. Меньше гибкости в настройке. Сложнее в отладке.
